## 13. 中间件降级有效 + Redis 无业务真源

**走查**：`redis.enabled=false` + 重启（执行文档许可的降级演练方式；另以"键不落库"互证）。**T19 收尾复验（中间件全 Docker 化后）**：直接 `docker stop weiguang-redis` 即真实触发降级——登录成功、订单列表 code=0、日志现降级 WARN 行；`docker start` + 重启后端后探测恢复、限流键复现于容器。
**证据**：

```
重启日志：命中降级行（"redis.enabled=false，限流与热点缓存全部走本地降级实现"）
降级期间：登录成功、订单列表 code=0（主线仍走通）
键不落库互证：降级期间连续登录后，Redis 中 rate:login:* 键数量=0（限流走了本地计数）
键抽查：Redis 现存键仅 browse:dedup:*（浏览去重）与 rate:*（限流）、TTL 有效 → 无订单状态/账本/聊天消息等业务真源
恢复：redis.enabled=true + 重启 → 探测日志"Redis 探测成功"，限流键与 TTL 复现
```

**结论：通过**。

### 19.2 验收点

- 首页右下角「AI 小助手」入口 → 独立聊天页；不改变底部 5 个 Tab。
- 问答覆盖：发布、接单、取消、确认完成、申诉/反馈、微光值/积分、隐私地址。
- 发布链路：描述 → 类型/标题/标签 → 时间 → 地址 → 紧急联系人 → 确认卡 → 发布成功。
- 安全约束：AI 不直接写库；`confirmToken` 一次性；地址归属、紧急联系人、待响应上限、敏感词全部复用 `OrderService.publish` 校验。
- 槽位保护：只发「帮我发布求助」不会生成发布草稿；未描述具体内容时点时间/地址，会继续追问而不是直接进入确认卡；确认接口会二次校验描述，旧脏会话自动清除。
- 类型纠偏：「打球/下棋/散步/陪」优先归为陪同外出；「厨房/水管/灯/上门」优先归为上门；「手机/线上/视频」归为远程，避免模型把不需要地址的活动一律判成远程。
- 地址展示：远程类型显示「远程不需要地址」；陪同/上门未选地址时显示「待选择地址」，选中后显示真实地址标签，避免类型与地址文案矛盾。
- 无地址直达：未保存地址时，聊天页直接展示「还差一个常用地址 / 去添加地址」，点击跳到「我的地址」；从地址页返回聊天页自动刷新地址选项，不再反复要求用户去资料里补地址。
- 草稿编辑：确认卡提供「编辑内容」，可改标题、描述、类型、时间、地址、急单；保存后旧 `confirmToken` 作废并重新校验缺失项，远程类型自动清空地址，仍需再次确认才发布。
- 会话保留：退出聊天页、切后台、去地址页后返回，2 小时内可恢复上次对话与草稿；发布成功、主动取消、退出登录/切换账号、超过 2 小时均清空，服务端返回 `EXPIRED` 时前端自动回欢迎页。
- 悬浮入口：首页「AI 小助手」可拖动，位置持久化，`z-index=9999` 高于弹窗遮罩和底部导航。
- 思考模式：管理端「配置管理」中 `ai.thinking` 按普通配置项编辑 `true/false`，保存即时生效；默认仍为 false，开启会增加延迟和 token。
- 模型配置：当前环境验证 `qwen3.8-flash` 可用，`qwen3.7-plus` 免费额度已耗尽；能力二/四默认改为 `qwen3.8-flash`，避免一直降级 mock。
